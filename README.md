# Лабораторная работа №7 - Study Catalog

Тема: развёртывание ранее созданного веб-каталога курсов на виртуальной машине (IaaS). По методичке №7 нужен **реальный облачный сервер и доступ по внешнему адресу**. Пока облачного аккаунта нет, пакет подготовлен и может быть проверен на локальной VM; это не замена облачного этапа.

## Вариант через Render (PaaS)

Методичка разрешает платформу для веб-приложений вместо облачной VM. Render разворачивает Flask-приложение как Web Service и выдаёт публичный HTTPS-адрес `*.onrender.com`.

1. Разместите **содержимое этой папки** в отдельном GitHub-репозитории. Файл `.gitignore` исключает локальные VM, базу и секреты.
2. В Render выберите **New → Blueprint** и подключите этот репозиторий. Файл `render.yaml` автоматически задаёт бесплатный веб-сервис, установку зависимостей, запуск Gunicorn и проверку `/health`.
3. После статуса **Live** откройте выданный Render адрес и `/health`. Сохраните скриншоты настроек сервиса и работающего каталога по публичному адресу для отчёта.

На бесплатном тарифе Render файловая система временная: база SQLite, регистрации и фото могут исчезнуть при перезапуске или простое сервиса. Для учебной демонстрации при необходимости зарегистрируйтесь заново. Не храните в таком режиме ценные данные. Облачный запуск пока не был выполнен и не указан в отчёте как готовый.

## Локальная проверка в VS Code

Откройте **эту** папку в VS Code, затем в её терминале:

```powershell
vagrant up
vagrant status
```

Откройте <http://127.0.0.1:8087/>. Страница здоровья: <http://127.0.0.1:8087/health>. Остановить VM: `vagrant halt`. Следующий запуск: `vagrant up`. Эта VM отдельная от лабораторных №3 и №4.

## Развёртывание в облаке после получения доступа

Выберите в облачной консоли Ubuntu VM (IaaS) с публичным IP и входом по SSH. Разрешите входящий TCP-порт 8080 только для нужного адреса на время учебного показа. Передавайте на VM только папку `study-catalog`, без локальных данных пользователей и ключей. На VM выполните:

```bash
cd study-catalog
sudo bash deploy-ubuntu.sh cloud
curl -f http://127.0.0.1:8080/health
```

После этого откройте `http://<публичный-IP>:8080/` с другого устройства. Для завершения лабораторной сохраните скриншоты облачной VM, страницы каталога по внешнему адресу и результат проверки `/health`. Создавать аккаунт и вводить платёжные данные должен сам владелец аккаунта.

Приложение запускается службой `study-catalog` через Gunicorn. Проверка на VM: `sudo systemctl status study-catalog --no-pager`. Логи: `sudo journalctl -u study-catalog -n 50 --no-pager`. База пользователей, аватары и секрет сессий хранятся в `/var/lib/study-catalog`. При переносе на другой сервер эти данные нужно переносить отдельно. Публичное применение регистрации и входа требует HTTPS; адрес HTTP здесь только для учебной демонстрации без реальных паролей.

- Исходники Study Catalog из лабораторной №4: курсы, уроки, регистрация, MFA, профиль и метрики.
