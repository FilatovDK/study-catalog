# Лабораторная работа №7 - Study Catalog

Тема: развёртывание ранее созданного веб-каталога курсов в облаке. Для лабораторной №7 выбран допустимый в методичке вариант PaaS - веб-сервис Render. Отдельная локальная VM через Vagrant сохранена для проверки и запасного показа.

## Вариант через Render (PaaS)

Study Catalog опубликован как отдельный бесплатный Python Web Service:

- Каталог: <https://study-catalog-lab7.onrender.com/>
- Проверка работы: <https://study-catalog-lab7.onrender.com/health>
- Панель сервиса: <https://dashboard.render.com/web/srv-dbtknsbl550s73divv9g>
- Исходники: <https://github.com/FilatovDK/study-catalog/tree/lab7-render>

Веб-сервис подключён к публичному репозиторию GitHub, ветка `lab7-render`. Он создан отдельно от `kursquest-online`; основные ветки и старые лабораторные не менялись. В Render заданы Python 3, бесплатный план, сборка `pip install -r requirements.txt`, запуск `gunicorn --workers 1 --bind 0.0.0.0:$PORT app:app`, проверка `/health` и переменные `DEPLOYMENT_MODE=Render (PaaS)`, `STUDY_CATALOG_PUBLIC_CATALOG=1`. Секрет сессий создан в панели Render и не хранится в коде.

Курсы и уроки открываются без регистрации. Для личного кабинета требуется регистрация и MFA. Во время проверки Render показал статус **Live**; главная страница, страница курса, урок и `/health` открылись по публичному адресу. Мини-тест в уроке принял правильный ответ.

Файл `render.yaml` сохраняет параметры развёртывания для повторного использования, но текущий сервис был настроен вручную через панель Render.

На бесплатном тарифе Render файловая система временная: база SQLite, регистрации и фото могут исчезнуть при перезапуске или простое сервиса. Для учебной демонстрации при необходимости зарегистрируйтесь заново. Не храните в таком режиме ценные данные.

## Локальная проверка в VS Code

Откройте **эту** папку в VS Code, затем в её терминале:

```powershell
vagrant up
vagrant status
```

Откройте <http://127.0.0.1:8087/>. Страница здоровья: <http://127.0.0.1:8087/health>. Остановить VM: `vagrant halt`. Следующий запуск: `vagrant up`. Эта VM отдельная от лабораторных №3 и №4.

## Альтернатива: облачная Ubuntu VM (IaaS)

Если вместо Render потребуется вариант IaaS, выберите в облачной консоли Ubuntu VM с публичным IP и входом по SSH. Разрешите входящий TCP-порт 8080 только для нужного адреса на время учебного показа. Передавайте на VM только папку `study-catalog`, без локальных данных пользователей и ключей. На VM выполните:

```bash
cd study-catalog
sudo bash deploy-ubuntu.sh cloud
curl -f http://127.0.0.1:8080/health
```

После этого откройте `http://<публичный-IP>:8080/` с другого устройства. Для подтверждения такого варианта сохраните скриншоты облачной VM, страницы каталога по внешнему адресу и результат проверки `/health`.

Приложение запускается службой `study-catalog` через Gunicorn. Проверка на VM: `sudo systemctl status study-catalog --no-pager`. Логи: `sudo journalctl -u study-catalog -n 50 --no-pager`. База пользователей, аватары и секрет сессий хранятся в `/var/lib/study-catalog`. При переносе на другой сервер эти данные нужно переносить отдельно. Публичное применение регистрации и входа требует HTTPS; адрес HTTP здесь только для учебной демонстрации без реальных паролей.
